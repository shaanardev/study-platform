# Biome to Oxlint/Oxfmt coverage audit

**Audited:** 12 October 2026
**Repository versions:** Biome CLI/schema 2.5.15 (`package.json`, `biome.jsonc`), Oxlint 1.82.0 (`cli/package.json`). Oxfmt is not installed or configured.

## Scope and current wiring

The root Biome config enables the `recommended` preset, `suspicious/noDeprecatedImports`, and all available rules in the `types`, `svelte`, `tailwind`, and `test` domains. It also enables full HTML-like parsing/linting for Svelte and HTML, CSS/JSON recommended rules, and the `organizeImports` assist. The exact config is in [biome.jsonc](biome.jsonc).

The repository does **not** currently run Oxlint or Oxfmt for the frontend: root `validate` and `lint:fix` invoke Biome on `src`. The CLI has Oxlint plus Biome on `src test`; its Oxlint config enables `import` and `vitest` plugins. Neither package currently runs Oxfmt. Therefore, “Oxlint can cover” below means a rule exists and would need to be enabled in the frontend lint configuration; it does not mean the frontend already has that coverage.

I checked the installed Biome 2.5.15 binary with `biome explain` and reviewed the [2.5.15 release notes](https://github.com/biomejs/biome/releases/tag/%40biomejs%2Fbiome%402.5.15). This version adds five rules covered by the configured `all` domains: `noSvelteExportLet` and `useSvelteKitRuneImports` (`svelte`), `noTailwindRawColors` (`tailwind`), and `noMeaninglessVoidOperator` and `useStrictBooleanExpressions` (`types`). They are included in the active-rule inventory below. `noTailwindRestyledComponents` and `noSvelteInspect` are still absent from 2.5.15. Other new nursery rules in this release, including `useLogicalProperties` (CSS), `noSelfImport` (project), `usePromiseRejectErrors`, `noMisplacedListElements`, and React/Astro-specific rules, are outside the configured domains or preset and are not active here. The release also fixes Svelte block comment formatting and improves HTML formatter and type-inference performance; these changes do not alter the Oxlint/Oxfmt coverage mapping.

Oxlint is a JavaScript/TypeScript linter and does not lint CSS, JSON, or Svelte/HTML templates. Oxfmt formats CSS, JSON, HTML, and Svelte, but formatting does not run lint rules. Its Tailwind class sorting and import sorting are separate optional formatter features, both disabled by default. See the [Oxlint/Oxfmt compatibility matrix](https://oxc.rs/compatibility.html), [Oxlint plugin docs](https://oxc.rs/docs/guide/usage/linter/plugins), [type-aware lint docs](https://oxc.rs/docs/guide/usage/linter/type-aware.html), and [Oxfmt sorting docs](https://oxc.rs/docs/guide/usage/formatter/sorting.html).

## Existing CLI Biome/Oxlint overlap

The `cli/**` Biome override already disables five checks because Oxlint config has corresponding rules: `noNonNullAssertion` → `typescript/no-non-null-assertion`; `useThrowOnlyError` → `typescript/only-throw-error`; `noExplicitAny` → `typescript/no-explicit-any`; `noImportCycles` → `import/no-cycle`; and `useIterableCallbackReturn` → `array-callback-return`. These are covered for the CLI. They do not establish frontend coverage because the root package does not run Oxlint.

## Migration decision checklist

Before deleting Biome, preserve or deliberately drop each uncovered surface above. The largest non-interchangeable pieces are CSS linting, Svelte/HTML template linting, and the four Biome 2.5.15 type-domain checks with no Oxlint equivalent. Test-domain parity requires enabling Vitest rules that the existing CLI config currently disables. Add Oxfmt to the scripts and configure import/class sorting only if those formatting assists are intended to remain.

The version-specific inventory was checked against the installed Biome 2.5.15 rule explanations (`pnpm exec biome explain <rule>`) and Oxlint 1.82's registry (`pnpm --dir cli exec oxlint --rules . --format=json`). Oxlint's registry shows available rules, not active severity: alternatives must still be enabled in the frontend config. Domain tables list all rules Biome activates there, including rules that Oxlint can replace; the gap table isolates the missing or materially partial checks.
